# 视频拉流加速

## 核心判断

**「视频网速慢」不是一个问题，是四类问题。** 九成的无效折腾，是把「账号总量限速」
当「单连接限速」去治——装了一堆多线程下载器，速度一点没变。

判定只有一个指标：**加速比 = N 连接吞吐 ÷ 1 连接吞吐**

- **≥ 2.2×** → 单连接限速，多线程能线性叠加，**能治**
- **1.4 ~ 2.2×** → 部分叠加，有总量或链路瓶颈，**治一半**
- **< 1.4×** → 账号或链路总量限速，**多线程工具完全无效**

## 四层模型

| 层 | 限速主体 | 客户端能否加速 | 手段 |
|---|---|---|---|
| L1 单连接 | 服务端对每条 TCP 连接封顶 | **能**，接近线性 | aria2 / Gopeed / N_m3u8DL-RE 分段并发 |
| L2 账号/会话 | 平台按账号限总带宽 | **不能**（绕过=违约，不做） | 只能走官方权益 |
| L3 运营商链路 | QoS、跨网、晚高峰 | **部分能** | DNS/CDN 优选、IPv6、自建中转、BBR |
| L4 本地链路 | WiFi、路由器 QoS、MTU | **能** | 5GHz/有线、关 QoS、MTU 1480 |

## 第一步：探测（30 秒）

```bash
python3 skill/scripts/speed_probe.py "<媒体直链>" --levels 1,4,8,16 --seconds 6
python3 skill/scripts/probe.sh                       # 不带参数 = 内置 100MB 自测
```

直链从播放页 DevTools → Network → 过滤 `media` / `m3u8` 里取一条 `.ts` / `.m4s` / `.mp4`。
带防盗链时补 `--referer "<页面URL>" --cookie "k=v"`。`.m3u8` 是播放列表，不要拿它测。

结果读法：

- **跑两遍**。同一 URL 两次可能差 0.5 左右，两遍跨档位就按保守那档取。
- **看绝对值**。加速比高但单连接只有 0.3 MB/s，先解决链路再谈叠加。
- **429 不是不支持分段**，是公共测速端点限流，等 2~3 分钟。
- **403/401 是防盗链**，补 referer/cookie，别误判。

## 第二步：按层处置

### L1 → 多连接叠加

| 工具 | 用法 |
|---|---|
| 自带 `scripts/mdl.py` | `python3 scripts/mdl.py "<url>" -o a.mp4 -x 8`，纯标准库，无需 aria2 |
| `aria2/aria2` | `aria2c -x16 -s16 -k2M -d ~/Downloads "<url>"` |
| `nilaoda/N_m3u8DL-RE` | HLS/DASH 分片并发，治「一片一片请求」的慢 |
| `yt-dlp/yt-dlp` | `-N 16 --downloader aria2c` |
| `agalwood/Motrix` / `GopeedLab/gopeed` | 图形界面下载器 |

**并发不是越大越好**。同一台机器实测：10 MB 文件，`-x4` 用 9.0 秒（1.17 MB/s），
`-x8` 用 13.8 秒（0.76 MB/s）——约 12 Mbps 的链路上，8 连接属于超订。
取探测里吞吐最高的那一档，别翻倍。

### L2 → 不做绕过

判定特征：加速比 < 1.4×，且同一账号播任何清晰度都卡在同一个数值。
说明三件事即可：违反用户协议有封号风险；要求粘贴 Cookie 的第三方「加速器」
多为账号盗取入口；合法路径是官方权益或转存到自己可控的存储。
不提供绕过手法。

### L3 → 换出口比堆并发有用

换 DNS（`223.5.5.5` / `119.29.29.29` / `1.1.1.1`）选更优 CDN 节点 →
优先 IPv6 → 线路好的云主机做反向代理中转 → 高丢包链路开 BBR。

### L4 → 免费且常被忽略

5GHz/有线优先、关路由器 QoS、MTU 试 1480、排除同网段大流量设备。

## 浏览器扩展（本仓库 `extension/`）

扩展改不了带宽，改的是**取数据的方式**：播放器一条连接顺序取分片，
扩展用多条连接把后续分片提前拉进浏览器 HTTP 缓存，播放器请求同一 URL 时命中缓存。

安装：`chrome://extensions` → 开发者模式 → 加载已解压的扩展程序 → 选 `extension/`。

两个**互斥**开关：

| 开关 | 行为 | 流量代价 |
|---|---|---|
| 存着慢慢看 | 后台缓存整片，之后随便拖都不卡 | 完整下载一次，上限 150 MB |
| 立刻享受 | 点进度条到哪就先缓冲哪一段 | 只改下载顺序，几乎不增加总量 |

角标会显示缓存策略判定；弹窗「实测是否命中」用 A/B 计时验证有没有真命中。

**扩展无效的情况**：单文件 mp4 / DRM / 纯直播流（无可解析分片表）、
CDN 返回 `no-store`（预取不进缓存）、播放器每次换分片签名（URL 不匹配）、
平台会员限速。前三种角标会直接说明，不会假装在工作。

## 合规边界

- **做**：多连接叠加单连接限速、CDN/DNS 优化、IPv6、自建中转、本地链路优化、
  并发下载自己有权访问的内容。
- **不做**：绕过平台会员权益限速、共享或盗用他人 Cookie、破解 DRM / 付费墙、
  抓取他人私有内容。
